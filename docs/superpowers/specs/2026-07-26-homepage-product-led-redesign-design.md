# 首页产品化改版设计

## 目标

将首页从“逐段解释能力的长文案页面”调整为更适合短视频、社交内容和搜索流量落地的产品化入口。页面要让首次访客快速看懂：这个开发者能做什么、如何交付、有哪些可查看的方向，以及如何开始沟通。

本次改版保留 `Ecosystem`。不删除项目、服务、流程、博客或联系入口；通过减少首页重复说明、用可扫描的 UI 组件承载信息，降低阅读负担。完整介绍和服务详情继续由 `/about` 与 `/services` 承载。

## 范围

- 调整首页的 About、Skills、Projects、Services、Process、Blog、Ecosystem、Contact CTA 的信息密度和视觉编排。
- 复用现有深色令牌、动画基础层、数据文件与路由，不引入图片素材、外部 API、Canvas 或新的依赖。
- 保持首页章节顺序、锚点和既有页面入口稳定。
- 不修改后台、CMS、AI、CRM、SaaS 或项目详情页。

## 首页叙事

1. **Hero**：保留现有主张与两个行动入口，承担第一眼定位。
2. **Profile Signal（About 首页预览）**：用一句定位、四个能力演进节点和少量真实上下文指标表达“我是谁”。不再在首页完整呈现长成长故事；“了解更多”链接至 `/about`。
3. **Capability System Map（Skills）**：保留四个可访问的能力域切换，但首屏只显示当前域的核心用途、技术集合和产品关系图。技术清单不与项目卡片重复堆叠。
4. **Case-study Rail（Projects）**：精选项目使用大面积抽象产品预览、问题一句话、解决方向和案例入口。项目技术标签仅在展开/详情语境出现，避免首页反复出现同一技术名词。
5. **Service Mode Switcher（Services 首页预览）**：首页只聚合为三类可选择合作模式：企业系统、AI 与自动化、产品 MVP/升级。每一模式显示适用情境和一个明确的咨询动作；六项完整服务仍位于 `/services`。
6. **Delivery Pipeline（Process）**：将当前流程改为单一横向/纵向五步时间线。选中步骤显示交付物，不使用长段落或多个重复卡片。
7. **Journal Shelf（Blog）**：保留三篇文章的封面、主题、阅读时间和标题；移除解释性重复文案，链接至 `/blog`。
8. **Build / Write / Connect（Ecosystem）**：保留章节，但将 GitHub、开放实验、技术活动与社交状态压缩成三个明确的状态模块。没有配置的账号不显示假链接；没有公开项目时只显示诚实的“正在整理”状态。
9. **Project Brief（Contact CTA）**：保留首页唯一最终转化入口，用一个大咨询面板承载主张、简短说明、主按钮和项目案例次入口。

## 组件边界

| 区域        | 首页职责             | 主要 UI 形态                          | 数据/路由边界                                                  |
| ----------- | -------------------- | ------------------------------------- | -------------------------------------------------------------- |
| About       | 快速建立信任         | 信号轨道、演进节点、指标列            | 复用 `src/data/about.ts`；完整内容链接 `/about`                |
| Skills      | 解释能力如何组合     | 无障碍 Tabs + 当前域详情 + 静态关系图 | 复用 `src/data/skills.ts`                                      |
| Projects    | 展示可理解的解决方向 | 大预览案例轨道                        | 复用项目数据；入口保持 `/projects`                             |
| Services    | 帮助访客匹配合作方式 | 三项模式切换器                        | 从服务数据映射；详情链接 `/services` 或 `/contact?service=...` |
| Process     | 降低合作不确定性     | 选中步骤的时间线                      | 复用流程数据，不创建额外 CMS 字段                              |
| Blog        | 引导持续阅读         | 杂志式文章架                          | 复用博客数据；入口保持 `/blog`                                 |
| Ecosystem   | 展现公开积累         | Build / Write / Connect 状态模块      | `open-source.ts`、`social.ts` 是唯一来源                       |
| Contact CTA | 首页终点             | 大型项目简报面板                      | 主入口 `/contact`，次入口 `/projects`                          |

## 视觉与交互约束

- 继续遵守 `DESIGN.md`：深色画布、细边界、克制紫色行动色、青色仅用于辅助连接状态。
- 每个首页章节只有一个主要视觉动作；不把所有信息塞进卡片网格。常规区域不超过三张同类卡片。
- 可交互选择器使用真实 button、tab 或 link；键盘焦点、Enter/Space、箭头导航和手机触控均可完成关键操作。
- Hover 只提示可操作性，不能隐藏核心信息。触摸设备与 `prefers-reduced-motion` 下使用静态、完整的文档流。
- 不增加新的连续动效。章节进入只用既有 Reveal；选项切换只用短 crossfade/边界反馈。
- 中文标题按语义换行，375px、768px、1024px 与 1280px 均保持自然阅读，不引入横向滚动。

## 去重规则

- 首页不再完整复制 `/about` 与 `/services` 的所有解释内容。
- 技术名称在同一个视口内只在一个主要区域作为重点出现；项目、服务、生态区使用“问题、方式、状态”而非重复技术墙。
- 真实未知数据维持空状态，不伪造 GitHub、开源仓库、社交链接、客户、项目成果或指标。

## 验收标准

- 首页保留 Hero、About、Skills、Projects、Services、Process、Blog、Ecosystem、Contact CTA 九个导航章节，`Ecosystem` 仍可由 `#ecosystem` 到达。
- 首页 About 与 Services 明显比独立 `/about`、`/services` 更精简，并各自提供可用的详情入口。
- 每个首页章节至少有一个明确的、非纯文字的 UI 组织方式，但不引入无意义图表、装饰卡片瀑布或额外运行时。
- 小屏不依赖 Hover、不出现内容裁切/横向溢出，核心行动链接可键盘与触摸访问。
- `pnpm typecheck`、`pnpm lint`、`pnpm build` 可以在改版后成功完成；本地首页可正常加载。

## 已接受边界

- 不在本次改版中补造真实项目截图、GitHub 链接、社交账号、客户成果、文章封面或业务数据。
- 不改变现有独立页面的信息范围；首页只承担预览和转化。
- 不重启或替换现有技术栈，不新增 3D 场景、视频、图表库或第三方服务。
