# 从零构建企业知识库 RAG 系统

企业知识库的目标不是“接上模型就能回答”，而是让回答能回到可信来源。一个可维护的 RAG 系统，需要把资料清洗、检索、上下文组织和人工校验拆成独立环节。

## 把知识进入系统的过程变得可追溯

每个文档至少应保留来源、版本、更新时间和可见范围。切分文本时，不要只按照固定字符数截断；标题、段落和表格的边界往往影响检索语义。

| 环节     | 输入                | 输出         | 需要确认的问题       |
| -------- | ------------------- | ------------ | -------------------- |
| 资料接入 | PDF、文档、网页导出 | 原始文件记录 | 来源是否允许使用？   |
| 文本处理 | 原始文件            | 结构化片段   | 标题和表格是否保留？ |
| 向量检索 | 用户问题            | 候选片段     | 相关性是否足够？     |
| 回答生成 | 候选片段            | 带引用的回答 | 是否能回到原文？     |

## 检索不是唯一的判断条件

向量相似度可以找到候选片段，但不能保证它们适合直接回答。一个稳妥的流程会先明确业务边界，再筛选相关资料，让模型只根据候选内容回答；证据不足时应该明确说“资料中没有足够依据”。

```python
def answer_question(question: str, tenant_id: str) -> AnswerDraft:
    chunks = retriever.search(question, filters={"tenant_id": tenant_id}, limit=6)
    if not chunks:
        return AnswerDraft(text="当前资料不足，建议补充原始文档。", sources=[])

    return generator.create_answer(question=question, sources=chunks)
```

这类伪代码强调两个原则：租户或权限过滤必须先于检索结果展示；回答对象应携带来源，方便页面展示与人工核验。

## 给人工校验留出位置

在业务场景里，RAG 更适合作为“带证据的查询入口”，而不是无条件的自动决策器。对于政策、报价、合规或流程例外，页面应允许使用者打开来源、标记问题和提交补充资料。

> 提示：模型输出中没有引用并不等于内容错误，但在企业知识库中，它通常意味着还不具备直接执行或对外承诺的依据。

## 小结

先保证资料、权限和引用链路可靠，再讨论更复杂的 Agent、自动工作流和知识更新频率。这样才能让 AI 功能真正进入可验证的业务过程。
